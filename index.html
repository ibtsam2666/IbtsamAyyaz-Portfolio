An AI-driven QA agent suite

14 agents
Given
QA capacity was the bottleneck: each tester could take 1–2 tickets per sprint through planning, testing and sign-off.

~500 tests / day

Mutation testing for assertions

tests the tests
Given
A green test is only useful if it would fail when the behaviour breaks.
Did
Wrote a mutation-testing agent that creates a separate mutated copy of a test for each assertion and checks that the test fails at that exact assertion.
Result
Weak or always-passing assertions are caught before they reach the regression suite.

Faster CI and one-step failure reruns

3–4 h → 30 min
Given
A full regression run took 3–4 hours in Jenkins, and recovering from a failed run took two people 1–1.5 days.
Did
Split the suite into independent parallel groups after validating data, login and test dependencies. Built Node.js utilities and Jenkins retry workflows that read Xray failures, restore the right test databases and rerun only the failed tests. Added an MCP server that reruns failed specs by Xray ID in parallel terminals and posts live pass/fail status to the JIRA ticket.
Result
Runtime fell to about 30 minutes, recovery to about 4–5 hours, and manual testing effort dropped by about 20 hours per sprint.
JenkinsXrayMCPSQL Server

How I work

Deciding what to test first

  1. Read the ticket, the acceptance criteria and the code change to see what the feature touches.
  2. Rank risk by user impact and likelihood: the core path, money or data that could be wrong, integrations and permissions, shared code that changed.
  3. Test those areas end to end and check the data behind the UI with SQL. One overnight shift that crossed midnight looked right on screen but split across two days in the database, which broke the overtime calculation.
  4. Then edge cases, cross-browser and device checks, and targeted regression around the change. Stable, repeatable checks get automated.
